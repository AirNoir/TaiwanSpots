# Islandia：後續 114 張製圖規範與踩坑紀錄

使用者 2026-10-19 授權從現在接續到隔天，完成其餘景點，於網頁逐張 review。工作佇列：`docs/overnight-art-progress.json`。原有 45 張 App 圖固定，後續只做收藏圖預覽，不輸出新 day/thumbnail/token，不改 src（產生器輸出除外）。

## 風格與取景：不是把真實照片直接過濾鏡

- 精緻 Q 版實體收藏玩具，環境與材質擬真，形狀適度圓潤；不可手繪筆觸、粗幾何、全尺寸實景照片。風格參考用已接受淡水 `assets/spots/tamsui/collection/review-v4.png`，只借材質、基座與收藏感，不複製地標。
- 約 45 度斜上方、長焦／弱透視的微縮移軸商品視角。鏡頭不滾轉、沒有廣角巨型前景、桶狀／全景變形或消失點漏斗。移軸感不等於把人縮成像素，也不等於僵硬、冷漠的衛星俯瞰。
- 留下人情味：少量自然散步、拍照、交談的可愛遊客，與景物同一尺度。不是為了看清臉把人放大十倍；也不為了塞下整區，把每個人做成不可見小點。先選擇較小、有代表性的真實取景範圍。
- 需要完整大尺度地理才能容納的遠方物件，寧可縮小取景、略去 crop 外物件，並記錄取捨；不要把遠方地標搬到主體旁、縮成桌上裝飾或加在假背景。
- 圖片原生輸出、不放大；原圖不烘焙減色。比較頁沿用 88% 顯示。禁止水晶球、玻璃罩、背景板／圖卡／支架／夾子、漂浮支柱、文字標籤與水印。

## 基座、水平、容納範圍

- 真正等邊正方形、淺象牙色基座：四條長直邊、四個小圓角（約邊長 4–6%），薄且一致的邊框。不能變長方形、圓形、自然海岸輪廓或不規則多邊形。
- 不可用直線切掉一個角形成第五／第六邊；不要缺口、凹槽、凸出軌道、後方偷偷接另一塊地。
- 所有建築、樹冠、岩石、水面、地形及轉子占地都落在內框內；超出就統一縮小或重選實際 crop，不裁切主體、不浮空。完整基座與頂端入鏡，四周有留白。
- 地坪、基座、建築共用一致透視；真正垂直的柱／門框／塔軸直立。不能把照片仰角、廣角造成的歪斜照搬。保留真實山坡、彎路、弧形屋頂、牆身收分、斜撐與地震斷拱，不把真實結構硬拉直。

## 實景、方位與比例

- 每一景點先讀 blueprint、執行 `npm run assets:prompt -- <id>`，不是直接相信 draft 文案。至少兩個獨立實景視角交叉看：地面／街景與衛星／鳥瞰。相同全景的兩份裁切不算兩個獨立角度。
- 有不清楚的結構再找官方實照／另一角度。來源 URL、作者／單位、拍攝或出版年代、授權／限制寫入 sources.json；原照保留，圖片不是 App 貼圖。Google screenshots 要載入完成、保留歸屬，不保存搜尋框的私人住址或帳號資訊。
- 廣角／魚眼／360／仰拍先辨識，再用獨立視角重建。缺少鏡頭係數，不得宣稱完成數學去畸變或精確正射測繪；不能對有深度的整個場景套單張 homography 然後說是正確地形。
- 人、建築、樹、車、岩石與風機用一致尺度。用已知尺寸判斷數量級，不能讓女王頭巨大、風機像小風車、牛與樹一樣高；同樣大小物體不可只因在後排就任意縮小。
- 方位以地圖和實照為準。街道不直衝車站門、建築不能放道路錯側；階梯升降看多張照片；車庫與鐵軌不做成凹碗。有限短街段比在小底座裡塞無限長街可靠。
- `verify:` 項目只有確認後才移除；不確定尺寸、背面、店面與目前施工狀況寫 pending。生成圖不能當下一張的地理證據。

## 已踩過的具體坑

- 象山：階梯朝城市下行、岩旁樹保留、101 周邊不可隨機塞森林；城市與地形全在同一基座。
- 日月潭：真實湖岸不等於基座輪廓；不能加不存在的中央圓圈。故宮／象山不可以超出邊框。
- 中正：移除鏡頭歪斜，但保留真實牆身收分與八角雙層藍屋頂。檜意村木柱、地坪、屋簷共用透視。
- 龍騰：墩身不因全景變形傾倒；斷拱不補成完整橋、不抹平真實破損。奮起湖軌道與車庫地坪同高，不捏造未核對的列車。
- 士林：劍潭站與北藝中心是分開區塊，道路隔開；入口面向人行空間，車道不鑽進入口。舊慈諴宮照片是另一 crop，不能誤用作南側入口證據。
- 故宮南院：深灰曲面實量體、肋架玻璃虛量體與連接部分都要核對；至美橋是有拱肋的平順橋面，不是 S 形樓梯。
- 高美：風機在南／西南側環港北路附近，不在木棧道後緣隨便排小風車；官方描述高度約 64m、棧道長約 691m。若整體地理範圍讓人物小到沒有人情味，取景本身就要重想，不是強行做更高的衛星視角。v5/v6 被使用者拒絕，App 暫採 v4；不要把拒絕稿當風格母版。
- 修相機／基座時，帶舊錯誤圖當 target 常會原封複製錯誤。反覆失敗應改用已接受風格圖＋實景重新構圖，不能只重複 square／orthographic 字眼。

## 每張與每批交付

1. 收集／檢視獨立實景，補 sources.json、blueprint references 和可證實的幾何，保留未確認欄位。
2. 保存 exact prompt 與 blueprint brief；內建 imagegen 每景點各生成一次，出圖立刻複製為該景點 `collection/review-vN.png`，不覆寫舊版。
3. 目視 QA：身份、真實相對位置、尺度／人情味、坡向、基座四邊、水平、容納範圍、材質、512px 可辨識度。明顯錯誤重做；最多兩次針對性修訂仍失敗就標 needs-regeneration，別當作完稿。
4. 合格預覽才加入 selections，更新 queue state 為 self-checked-preview，userAcceptance 仍 pending；不能用 pass 字串當作實際檢查。未有充分來源的景點保留 blocked-reference，不亂補。
5. 每批執行 `node scripts/build-asset-comparison.mjs` 與 `node scripts/build-art-production-progress.mjs` 更新比較頁與進度頁（docs/art-production-progress.html），確認新圖、實照可載入。保護既有 45 筆 selections、114 個 runtime WebP 的 SHA-256。不跑 assets:export，不改 App 邏輯。
6. 每批執行 assets:registry、assets:check、spots:check、lint、typecheck 與 git diff --check；只提交本批檔案，再 push。7 張既有 untracked docs preview JPG 不屬本批。
7. 生圖額度／工具不可用時保留確切完成清單與阻擋原因，不偷換 API／模型、不填假成功、不無限重試。後續從 queue 繼續，不重做已完成圖。

夜間自動接續：每輪挑 5 個 queued 景點，能完成就繼續；以 2026-10-20 09:00 Asia/Taipei 為這次時間界線，完成全部或到界線後停止新出圖並總結。沒有變動時保持安靜；有額度／工具阻擋、全部完成或需要人處理才通知。
